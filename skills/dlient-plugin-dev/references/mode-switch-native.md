# Mode switch: UI-only (`default`) → native (UI + worker + vendored native modules)

This guide converts a **UI-only** plugin (scaffolded with no flag) into the **native** mode:
UI + worker + native `.node` modules **vendored into `dist/`** and rebuilt against the host's
Electron ABI with `@electron/rebuild` (`npm run build:native`). It corresponds to the
`templates/native` scaffold, produced by `npx @dlient-open/create-plugin <id> --native`.

It reuses the worker files, so it is the `worker` mode plus a vendored-native build step.

## 1. When to choose this mode

Choose `native` when the plugin needs `.node` addons (e.g. `better-sqlite3`, `ssh2`, `node-pty`,
image/audio codecs) that cannot load inside the sandboxed worker, **and** you want the prebuilds
shipped inside the `.dlient` (self-contained, no install-time npm step on the user's machine).

Prefer the **native-host** mode (`dlient.nativeModules`) for new projects: it installs the native
packages user-side and loads them in an official-Node child, so there is **no per-platform rebuild**.

| | `native` (this guide) | `native-host` (`dlient.nativeModules`) |
| --- | --- | --- |
| ABI | Electron ABI, rebuilt per platform with `@electron/rebuild` | **official Node ABI** (no rebuild) |
| `.node` ships in | `dist`, vendored (must declare `platforms`) | not packaged; installed user-side with npm |
| Build step | `npm run build:native` on every target platform | none extra |

**Do not** use this mode when there are no native modules, or when a pure-JS alternative exists — a
vendored prebuild must be built **separately on each target platform**, and it raises the install-time
trust level. Stay **UI-only** (`default`) if no native code is needed; use the plain **`worker`** mode
if you only need Node code without `.node` addons.

> The two native paths are mutually exclusive: declare **either** `dlient.native` **or**
> `dlient.nativeModules`, never both. See `references/native-host.md`.

## 2. Files to add

Copy the worker files from `.agent/example/worker/` and take
`script/build-native.mjs` from the analogous `native` scaffold (`.agent/` does not ship a
`native` example; the file is the same one generated by `npx @dlient-open/create-plugin <id> --native`).

| Copy from | To (project) | Notes |
| --- | --- | --- |
| `.agent/example/worker/src/main/index.ts` | `src/main/index.ts` | Worker entry — `createWorkerRpc('<plugin-id>')`, one example handler (+ the optional `grant` handler) |
| `templates/native/script/build-native.mjs` | `script/build-native.mjs` | Vendors the `.node` prebuilds into `dist/` and rebuilds them for the current platform via `@electron/rebuild` |
| `.agent/example/worker/build-worker.mjs` | `script/build-worker.mjs` | esbuild build → `dist/worker.js` (also emits `dist/native-host.js` if `src/native-host/` exists) |

The example uses the placeholder `__PLUGIN_ID__` — replace it with your plugin id (the scaffolder
already does this for generated projects).

Resulting layout (native-specific files marked `+`):

```
my-plugin/
├── package.json
├── script/
│   ├── build-clean.mjs
│   ├── build-native.mjs        # + added (vendors + rebuilds the .node prebuilds)
│   ├── build-worker.mjs        # + added
│   └── make-dlient.mjs
├── skills/
│   └── SKILL.md                # + added (see §5)
├── src/
│   ├── main/
│   │   └── index.ts            # + added
│   └── renderer/               # UI (unchanged)
└── .agent/
```

## 3. `package.json` changes

### 3.1 `scripts`

Add `build:worker`, `build:native` and `dev:watch:worker`, append `build:worker` **and**
`build:native` to the `build` chain, and (for the combined `dev` watch) add `concurrently`:

```jsonc
"scripts": {
  "build": "node script/build-clean.mjs && npm run typecheck && npm run build:ui && npm run build:worker && npm run build:native",
  "typecheck": "tsc --noEmit",
  "build:ui": "vite build",
  "build:worker": "node script/build-worker.mjs",
  "build:native": "node script/build-native.mjs",
  "pack": "npm run build && node script/make-dlient.mjs",
  "prepublishOnly": "npm run pack",
  "dev:watch": "vite build --watch",
  "dev:watch:worker": "node script/build-worker.mjs --watch",
  "dev": "concurrently -k \"npm:dev:watch\" \"npm:dev:watch:worker\""
}
```

| Change | Why |
| --- | --- |
| `build:native` → `node script/build-native.mjs` | Vendors the `.node` prebuilds into `dist/` and rebuilds them for the current platform |
| `build` gains `&& npm run build:native` | One `npm run build` still builds everything |

### 3.2 `dlient` manifest fields

```jsonc
"dlient": {
  "native": true,
  "platforms": [
    "win32.x64", "win32.arm64",
    "darwin.x64", "darwin.arm64",
    "linux.x64", "linux.arm64"
  ]
}
```

| Field | Value | Notes |
| --- | --- | --- |
| `native` | `true` | `.node` prebuilds are vendored into `dist/`; **mutually exclusive** with `nativeModules` — never declare both |
| `platforms` | subset of the six OS.arch combos | **Required** with `native` — the vendored prebuilds are platform-bound, so list only the combos you build for |

### 3.3 devDependencies

```jsonc
"devDependencies": {
  "@electron/rebuild": "^3.6.0",
  "esbuild": "^0.20.0",
  "concurrently": "^9.1.0"
}
```

- `@electron/rebuild` — rebuilds the vendored native modules against the host's Electron ABI (per platform).
- `esbuild` — required by `script/build-worker.mjs` (`concurrently` only for the combined `dev`).

Run `npm install` afterwards.

## 4. Permissions & the expose policy

Add to `dlient.permissions`:

```jsonc
"permissions": ["log"]
```

`log` lets the worker write to its own log (`rpc.log.write` → `plugin-data/<id>/logs/main.log`) with
no fs permission. Add the other host-api keys your worker actually calls (`fs.read`, `child.spawn`,
`app.data`, …); resource access additionally needs `fsDirs` / `spawnCmds` or a runtime grant.

> **Expose policy — expose as little as possible.** Add `dlient.expose` entries **only** if another
> plugin genuinely must call this one (or the user explicitly asks). A plugin can expose methods
> **only if it actually ships a worker** — i.e. its build output contains `dist/worker.js`; the
> manifest `type` is irrelevant, and because this mode ships a worker it is free to expose. When you
> do expose:
>
> - prefer to also expose the `grant` handler (recommended, not required)
>   (`"expose": { "grant": { "description": "…", "access": "default" } }`)
>   and prefer returning `{ status: 'ask' }` so the user decides at call time;
> - return `{ status: 'deny' }` for anything touching user privacy, passwords, keys or tokens.
>
> See `references/worker.md` §4.2–4.3.

## 5. `skills/SKILL.md`

Ship an agent skill **only now** that a worker exists — a UI-only plugin must not include `skills/`.
Minimal skeleton:

````md
---
name: "__PLUGIN_ID__"
description: "One line: what this plugin does and when an agent should invoke it."
---

# __PLUGIN_ID__

One paragraph: what the plugin does and the host capabilities it uses.

## Methods

| Method | Args | Returns | Description |
| --- | --- | --- | --- |
| `__PLUGIN_ID__.greet` | `name?` | `string` | Return a greeting message |

## Example

```ts
const msg = await rpc.plugin.invoke('__PLUGIN_ID__', '__PLUGIN_ID__.greet', ['world'])
```
````

Keep `skills/SKILL.md` under `skills/`; it is packed into the `.dlient` as-is.

## 6. Verify & revert

**Build**

```bash
npm install
npm run build         # → dist/remoteEntry.js (UI) + dist/worker.js (worker) + vendored/rebuilt natives in dist/
```

Confirm `dist/worker.js` exists **and** the vendored `.node` prebuilds are present (and rebuilt) in
`dist/`. The host only forks a worker when `dist/worker.js` is present. Because the prebuilds are
platform-bound, run `npm run build:native` on **every** target platform before packing.

**Confirm the host loads it**

1. Dev flow: place the project under `dlient-open/plugins/<pluginId>` and run `npm run dev`
   (output-level watch). Reopen / reload the host to pick up changes.
2. Import flow: `npm run pack`, then host console → **"Import plugin"** → pick the `.dlient`.
   The vendored prebuilds travel inside the package — no user-side npm step.
3. Check `USER_DATA/plugin-data/<pluginId>/logs/main.log` (`USER_DATA` = `~/.dlient-open`) — you
   should see the worker's `log` lines.

**Revert**

- back to **`worker`** (drop the native build only): delete `script/build-native.mjs`, remove the
  `build:native` script and the `&& npm run build:native` step from the `build` chain, remove
  `dlient.native` (and `platforms` if it was only there for native), drop `@electron/rebuild` and the
  vendored prebuilds; keep `src/main/`, `dist/worker.js`, `skills/` and `dlient.expose`.
- back to **`default`** (pure UI): do the above **and** apply the revert note in
  `references/mode-switch-worker.md` §6 (delete `src/main/`, the `build:worker` / `dev:watch:worker`
  scripts, `dlient.expose` and `skills/`; make sure the UI no longer calls the worker).
